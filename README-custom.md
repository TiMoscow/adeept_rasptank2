# RaspTank Docker

Docker-контейнер для управления танком Adeept RaspTank ADR013-V4 на Raspberry Pi 5.

Проект без привязки к путям: везде ниже используются плейсхолдеры.
При установке подставляйте свои значения:

- `<путь_к_клону_репозитория>` - где склонирован этот репозиторий
- `<IP_хоста>` - IP-адрес Pi в локальной сети
- `<URL_репозитория>` - адрес твоего репозитория на GitHub
- `<пользователь>` - системный пользователь, от которого работает Docker

## Быстрый старт

```bash
cd <путь_к_клону_репозитория>

# Собрать образ (первый раз, 10-20 минут)
docker compose build

# Запустить
docker compose up -d

# Проверить
docker ps --filter name=rasptank
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:5000/
# Должно быть: 200
```

## Доступ

- Веб-интерфейс: `http://<IP_хоста>:5000`
- Видеопоток: `http://<IP_хоста>:5000/video_feed`
- Зуммер писк: `http://<IP_хоста>:5000/api/buzzer/beep`
- Зуммер песня: `http://<IP_хоста>:5000/api/buzzer/song`
- Зуммер стоп: `http://<IP_хоста>:5000/api/buzzer/stop`
- Переворот камеры на 180°: `POST http://<IP_хоста>:5000/api/camera/flip` (GET - текущее состояние)
- Фото: `POST http://<IP_хоста>:5000/api/photo` (тело `{"dir": "подпапка"}`)
- Съемка по расписанию: `POST /api/timelapse/start` (`dir`, `interval` в секундах, `max_count`, `duration`), `POST /api/timelapse/stop`, `GET /api/timelapse/status`
- Папки и список снимков: `GET /api/photo/config`, `GET /api/photo/folders?dir=`, `GET /api/photos?dir=`, `GET /api/photos/file/<путь>` (`?download=1` - скачать)
- Создать папку: `POST /api/photo/mkdir` (тело `{"dir": "подпапка"}`)
- WebSocket управления: `ws://<IP_хоста>:8888`
- Заряд батареи: `GET /api/battery` (напряжение и проценты)
- Дисплей: `GET /api/oled/status` (режим, выбранные строки, значения и настройки), `POST /api/oled/items` (тело `{"items": ["time", "temp", ...]}`, порядок пунктов это порядок строк на дисплее в режиме «Данные»), `POST /api/oled/mode` (тело `{"mode": "data"}`, `eyes` или `radar`), `POST /api/oled/options` (настройки режимов, частичный объект)
- Перезагрузка контейнера: `POST /api/system/restart` (см. раздел «Перезагрузка контейнера из веба»)

## Фото и съемка по расписанию

Панель «Фото» в веб-интерфейсе стоит в конце страницы, сразу за сеткой блоков управления (как и панель «Дисплей», а «Инструкция» в самом конце): кнопка «Сделать фото», выбор папки и съемка по расписанию с заданным интервалом. Кнопка «180°» осталась под окном камеры.

- Фото лежат в `PHOTOS_DIR` (в контейнере `/photos`). На хосте это `./photos` рядом с `docker-compose.yml` или путь из `PHOTOS_HOST_DIR`.
- Папку выбирают кнопкой «Выбрать папку»: открывается внутренний обзор папок, можно заходить внутрь, возвращаться наверх и создавать новые папки. Выбор подтверждается кнопкой «ОК». Под полем показан полный путь, куда ляжет файл. У ручного фото и съемки по расписанию папки независимые: в секции «Фото» своя, в секции «Съемка по расписанию» своя. Пока папка не выбрана, кнопки «Сделать фото» и «Запустить съемку» не срабатывают: панель предупреждает, что сначала надо указать, куда сохранять.
- Интервал и лимит времени задаются нативными пикерами времени в формате ЧЧ:ММ:СС (например, интервал `00:00:01`, лимит `00:00:09` дает 9 кадров по одному в секунду).
- Имя файла `ГГГГММДД_ЧЧММСС.jpg`. Папка только внутри `/photos`, до 3 уровней вложенности.
- На фото нет рамок и меток OpenCV, кадр уже перевернут, если включена кнопка «180°».
- Съемка по расписанию сама останавливается: по истечении лимита времени, при нехватке места (порог `PHOTOS_MIN_FREE_MB`) и после 5 ошибок подряд. Количество кадров задается интервалом и временем съемки, отдельного лимита кадров в панели нет.

| Переменная | Значение по умолчанию | Что делает |
| --- | --- | --- |
| `PHOTOS_DIR` | `/photos` | Папка для фото внутри контейнера |
| `PHOTOS_HOST_DIR` | `./photos` | Папка на хосте (подставляется в `docker-compose.yml`) |
| `PHOTOS_MIN_FREE_MB` | `200` | Ниже этого порога свободного места съемка не идет |
| `PHOTOS_JPEG_QUALITY` | `95` | Качество JPEG |
| `PHOTOS_UID`, `PHOTOS_GID` | не заданы | Владелец файлов на хосте, иначе файлы будут от root |
| `TIMELAPSE_RESUME` | не задана | `1` - продолжать съемку после перезапуска контейнера |
| `TZ` | `Europe/Moscow` | Часовой пояс для имен файлов |

После обновления нужна пересборка образа (в `Dockerfile` добавлен `tzdata`) и пересоздание контейнера:

```bash
docker compose build
docker compose up -d --force-recreate
```

## OLED-дисплей

На разъеме X1 (I2C) стоит OLED 0.96 дюйма на SSD1306, адрес `0x3C`. Режим и содержимое задаются в веб-интерфейсе, в панели «Дисплей».

Режимов три, выбран ровно один:

- **Данные** - строки со значениями: время, дата, температура CPU, память, загрузка CPU, процент батареи, uptime. Порядок строк на экране совпадает с порядком пунктов в панели, первый пункт рисуется вверху. Крестик убирает строку с дисплея, максимум 8 строк, выше не влезет, экран 64 пикселя высотой.
- **Глаза** - персонаж с эмоциями: моргает, зрачки блуждают, засыпает после простоя (`sleep_after`, по умолчанию 120 секунд без событий), грустит при заряде ниже порога (`bat_low`, по умолчанию 20%), пугается на препятствие и человека. Что учитывать, задается галочками «Реагировать на», порог препятствия (`obstacle_cm`, по умолчанию 30 см).
- **Радар** - полукруг с дальномером, который смотрит вперед вместе с камерой. Сервопривод камеры радар НЕ крутит: скан сервой только мешает и ломает вид с камеры, поэтому движений привода в этом режиме нет. Точка препятствия рисуется по центру луча.

Набор строк и настройки лежат в `web/.oled_config` (JSON: режим, список строк, настройки глаз), переживает рестарт. Нет файла, значит вид по умолчанию: режим «Глаза», в строках время, температура, память, загрузка CPU.

`web/oled_display.py` - фоновый поток рендера, кадры 15 раз в секунду, значения собираются раз в секунду. Если дисплея нет на шине, поток тихо завершается, сервер работает дальше.

`web/oled_sources.py` - источники для экранов: дальномер, события (команды из веба, препятствие, лицо). Фоновые наблюдатели препятствия и лица поднимаются только для режима «Глаза», для радара - скан дальномером. `web/oled_screens.py` - отрисовка самих экранов (строки, глаза, радар). Замер дальномера в `web/ultra.py` взят под лок: движение и экран ходят к сенсору из разных потоков.

- Температура читается из `/sys/class/thermal/thermal_zone0/temp` (миллиградусы), память и CPU через `psutil`, батарея через тот же код АЦП, что и `/api/battery`.

Проверка дисплея:

```bash
# Адрес 0x3C должен быть виден в строке 30
sg docker -c 'docker exec rasptank_web i2cdetect -y 1'
```

## Огни робота

На плате лента WS2812 из 16 диодов (SPI), код в `web/robotLight.py`.

Кнопка «Огни робота» в карточке «Действия» (в оригинале она звалась POLICE LIGHT) за один клик переводит ленту в следующее положение, всего положений четыре:

| Положение | Что показывает | Команда | Цвет кнопки |
| --- | --- | --- | --- |
| Полиция | красно-синие вспышки | `ledPolice` | красный |
| Мигание | плавная пульсация синим | `ledBreath` | синий |
| Ровный | синий без мигания | `ledSteady` | голубой |
| Выкл | лента погашена | `ledOff` | серый |

Обход по кругу такой: мигание, ровный, выкл, полиция, снова мигание. Команды уходят на WebSocket 8888, своих эндпоинтов HTTP у огней нет.

Текущее состояние огней сервер наружу не отдает. Поэтому после перезагрузки страницы кнопка всегда нарисована как «мигание», даже если на ленте сейчас другое положение. Это известное ограничение, обошлось бы только новым полем в протоколе.

### Пульсация и яркость

- Пульсация синяя, цвет задан очень тусклым: пик всего 4 из 255. Так и задумано, чтобы диоды не били в глаза.
- Один цикл вдох-выдох идет 1.8 секунды.
- У ленты восемь бит на канал, а при пике 4 промежуточных яркостей получается всего пять (0, 1, 2, 3, 4). Переход шел бы заметными ступеньками. Чтобы он был ровным, внутри каждого шага быстро чередуют два соседних уровня, и глаз видит среднее.
- Переписывать ленту каждый раз не нужно, запись идет только когда значение изменилось. Выходит около 125 записей в секунду вместо тысячи.

## Перезагрузка контейнера из веба

В шапке веб-интерфейса, справа от кнопки EN|RU, стоит кнопка с иконкой перезагрузки. По нажатию спрашивает подтверждение, после согласия показывает оверлей «Контейнер перезагружается», а когда сервер снова отвечает, страница обновляется сама.

Как это устроено:

- `POST /api/system/restart` (в `web/app.py`) сначала отвечает клиенту, через секунду останавливает моторы, чтобы робот не уехал, и завершает процесс через `os._exit(0)`.
- После подъема контейнера сервоприводы возвращаются в 90 плавно, без рывка (см. раздел «Плавный старт сервоприводов»).
- Сигналом тут не выходит: PID 1 в контейнере ядро не убивает штатными сигналами без явного обработчика (защита init-процесса), ни своими `os.kill`, ни внешним `docker kill --signal=SIGTERM`. Поэтому процесс выходит сам.
- Процесс завершается, а `restart: unless-stopped` из `docker-compose.yml` поднимает контейнер заново. Docker socket на хост не монтируется, дополнительных зависимостей нет.
- Пока контейнер поднимается, `web/dist/restart.js` опрашивает `/api/camera/flip` раз в 1.5 секунды и делает `location.reload()`, как только приходит ответ. Если через 2 минуты тишина, оверлей предлагает подождать дальше или обновить страницу вручную.
- Тексты EN/RU берутся из `localStorage['lang']`, как у остальных кастомных панелей.

Ограничение: перезагрузка возможна только при `restart: unless-stopped` в compose. Если контейнер запущен вручную через `docker run` без политики перезапуска, он после завершения процесса просто остановится.

## Плавный старт сервоприводов

У сервоприводов нет датчика положения, поэтому программа не может узнать, где серва стоит. Вместо этого она запоминает последний угол, который сама отправила, и при старте начинает движение от него.

Откуда берется стартовая точка (по порядку):

1. Регистры чипа PCA9685. Если чип не обесточивался (перезапуск контейнера кнопкой или `docker restart`), он продолжает выдавать последний импульс, и регистры содержат реальное положение.
2. Файл `web/.servo_state.json`. Каждые 0,2 секунды (только если углы менялись) в него записывается последний угол каждого канала. Файл переживает полное отключение питания.
3. Если неизвестно ничего (самый первый запуск, файл удален или поврежден), серва сразу ставится в целевой угол. Один рывок в этом случае неизбежен.

Дальше `moveInit` в `web/RPIservo.py` делает три шага: первым импульсом отправляет стартовый угол (серва стоит на месте), ждет 0,3 секунды и плавно, с мягким стартом и остановкой, ведет каждую серву к `initPos`. Время не меньше `scTime` (2 секунды) и такое, чтобы скорость не превышала 40 градусов в секунду (`START_MAX_SPEED`).

Ограничения, которые программой не лечатся:

- Если серву сдвинули руками, пока робот был без питания, или рука опустилась под своим весом, физический угол к первому импульсу отличается от сохраненного. Серва один раз резко доедет до сохраненного угла (рывок равен смещению), потом плавно поедет к целевому. Перед выключением лучше опускать руку на упор.
- При резком отключении питания во время движения сохраненный угол может отставать не более чем на 0,2 секунды движения.
- Плавным сделан только старт. Кнопки интерфейса, которые ставят серву в позицию (`moveServoInit`, `setPWM`), по-прежнему двигают ее сразу.

Проверка без железа: `python3 -m unittest discover -s tests -p "test_servo_start.py" -v`.

## Управление контейнером

```bash
# Остановить
docker compose down

# Перезапустить (после правки кода)
docker compose restart

# Пересоздать (после изменения docker-compose.yml)
docker compose up -d --force-recreate

# Пересобрать (после изменения Dockerfile)
docker compose build

# Логи
docker logs -f rasptank_web

# Войти внутрь
docker exec -it rasptank_web bash
```

Если пользователь не в группе `docker`, добавлять `sudo` перед каждой командой.

## Кастомные правки

Все свое живет только в ветке `custom`:

- `web/app.py` - эндпоинты зуммера `/api/buzzer/beep`, `/api/buzzer/song`, `/api/buzzer/stop`. Стоп мелодии через `threading.Event`
- `web/robotLight.py` - `try/except` вокруг `from rpi_ws281x import *`, чтобы код запускался там, где библиотеки нет
- `web/switch.py` - урезан под робота
- `web/camera_opencv.py` - переворот кадра на 180° через `cv2.flip` (флаг `flip180`, состояние в файле `.camera_flip`, переживает рестарт). Для камеры, закрепленной шлейфом вверх ногами
- `web/dist/index.html` - кнопка переворота камеры в карточке Video (логика и стили в `web/dist/js/lang.js`)
- `web/dist/js/lang.js` + `web/dist/lang.json` - перевод интерфейса на русский и кнопка EN|RU в шапке. Исходников фронта нет (только собранный Vue), английский зашит в бандл, русский подменяется поверх DOM, выбор языка помнится в localStorage
- `web/dist/index.html` - сетка перебалансирована под длинные русские подписи: 5+4+3 вместо 6+4+2, правый столбик с карточкой «Действия» шире. Плюс перенос текста в кнопках как страховка
- `web/photos.py` - новый модуль: снимок, съемка по расписанию, безопасные папки, защита от нехватки места
- `web/app.py` - эндпоинты `/api/photo`, `/api/photo/config`, `/api/photo/mkdir`, `/api/photo/folders`, `/api/timelapse/*`, `/api/photos*`
- `web/camera_opencv.py` - `get_clean_frame()` (кадр без рамок OpenCV), один `imencode` на кадр вместо двух
- `web/dist/custom.js`, `web/dist/custom.css`, `web/dist/index.html` - панель фото в интерфейсе. Панель фото и панель дисплея стоят в конце страницы, за сеткой блоков: `custom.js` вставляет панель фото сразу за сеткой, `oled.js` - сразу за фото
- `web/dist/layout.js` - держит порядок блоков в конце страницы: панели фото и дисплея после сетки, инструкция в самом конце. Vue-пересборку переживает через MutationObserver, как и остальные панели
- `web/app.py` - эндпоинт `/api/battery`: заряд с АЦП ADS7830 на I2C `0x48` (код как в родном `web/Voltage.py`), тот же замер отдает процент батареи для OLED. Панель управления показывает заряд в шапке
- `web/oled_display.py` + `web/dist/oled.js` + `web/app.py` + `Dockerfile` - индикатор на OLED (SSD1306, I2C `0x3C`, разъем X1) с тремя эксклюзивными режимами в веб-панели «Дисплей»: данные (строки со значениями), глаза (персонаж с эмоциями, реакция на препятствие и лицо, грусть при низком заряде, сон после простоя), радар (полукруг с дальномером). Настройки и набор строк лежат в `.oled_config`, эндпоинты `/api/oled/status`, `/api/oled/items`, `/api/oled/mode`, `/api/oled/options`, библиотека `adafruit-circuitpython-ssd1306` добавлена в pip-список Dockerfile
- `web/oled_sources.py` - фоновые наблюдатели для экранов: дальномер, препятствие, лицо в кадре камеры. Поднимаются только когда нужны активному экрану
- `web/oled_screens.py` - отрисовка экранов OLED: строки, глаза с эмоциями, радар
- `web/ultra.py` - лок вокруг замера дальномера: движение и экран радара ходят к сенсору из разных потоков
- Радар на дисплее не крутит сервопривод камеры: дальномер смотрит вперед вместе с камерой, скан сервой убран, чтобы не ломать вид с камеры
- `web/WebServer.py` + `web/dist/js/lang.js` + `web/dist/lang.json` + `web/dist/custom.css` - кнопка «Огни робота» (бывшая POLICE LIGHT) с четырьмя положениями по кругу: полиция, мигание, ровный, выкл. Команды `ledPolice`, `ledBreath`, `ledSteady`, `ledOff` уходят по WebSocket, клик перехватывается на фазе захвата в `lang.js`, цвет кнопки задают классы `rl-st0`..`rl-st3`
- `web/robotLight.py` - плавная пульсация ленты: цикл замедлен до 1.8 секунды, для ровного перехода добавлен дизеринг, лишние записи на шину пропускаются
- `web/app.py` + `web/dist/restart.js` + `web/dist/index.html` + `web/dist/custom.css` - кнопка перезагрузки контейнера в шапке: эндпоинт `/api/system/restart` гасит моторы и завершает процесс PID 1 через `os._exit(0)` (политика `unless-stopped` поднимает контейнер заново), кнопка с подтверждением и оверлей ожидания с автообновлением страницы
- `web/RPIservo.py` - плавный старт сервоприводов: последний угол каждого канала хранится в `web/.servo_state.json`, `moveInit` едет от сохраненного положения (или от регистров чипа, если питание не пропадало) к 90 со скоростью не выше 40 градусов в секунду
- `tests/test_servo_start.py` - проверка плавного старта без железа (симуляция PCA9685)
- `Dockerfile`, `docker-compose.yml`, `.dockerignore`, `README-custom.md` - Docker-обвязка, в оригинале таких файлов нет

## Перед запуском на новой системе

1. Установить Docker: `curl -fsSL https://get.docker.com | sudo sh`
2. Добавить пользователя в группу docker: `sudo usermod -aG docker <пользователь>` (после этого перелогиниться)
3. Включить I2C и SPI: `sudo raspi-config` -> Interface Options
4. Настроить камеру в `/boot/firmware/config.txt`:

```text
[pi5]
dtoverlay=ov5647
dtoverlay=nospi10
dtoverlay=dwc2,dr_mode=peripheral
```

1. Склонировать репозиторий в `<путь_к_клону_репозитория>`
2. Собрать и запустить (см. Быстрый старт)

## Автозапуск

Двух уровней хватает:

```bash
# 1. Docker сам стартует после перезагрузки
sudo systemctl enable docker

# 2. Контейнер сам поднимается после старта Docker
#    Это уже прописано в docker-compose.yml:
#    restart: unless-stopped
```

Дополнительный systemd-сервис для контейнера не нужен.

## Обновление кода

Код смонтирован как volume. Правки на хосте видны сразу, но нужен перезапуск:

```bash
nano <путь_к_клону_репозитория>/web/app.py
docker compose restart
```

## Проблемы

**Контейнер рестартует в цикле** - смотреть логи:
```bash
docker logs rasptank_web
```

**GPIO busy** - другой процесс держит пины. Проверить, не запущен ли WebServer.py на хосте.

**Камера не видна** - проверить оверлей:
```bash
grep ov5647 /boot/firmware/config.txt
```

**Робот выключается при запуске** - батарея разряжена. Зарядить до 8.4 В.
